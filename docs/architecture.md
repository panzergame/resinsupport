# Architecture

| Layer | Crate | Role |
|---|---|---|
| L0 | `geom` | vectors, bounding boxes, triangle meshes and their measures (area, volume), ray hits (watertight test, BVH), segment and triangle distances (BVH box queries), spheres and frustums |
| L1 | `render` | headless view math: the camera, projections, view animations, grid and axis geometry |
| L3 | `io` | model file import (STL binary and ASCII), project files (`.rsup`), crash-safe writes |
| L4 | `engine` | the session (scene: models, support tips, selection; camera; undo history) and the command registry |
| L5 | `ui-egui` | the egui front end: viewport renderer (wgpu), navigation, menus, panels |
| apps | `resinsupport` | the desktop app |

L2 is kept free for the print job (printer profile, placement, supports), which will sit between the view math and the file formats. Support tips live in `engine::Scene` until supports get settings and generation, then move there.

## Commands
`Session::execute(id, params)` looks the id up in `crates/engine/src/cmd.rs`, runs it on a clone-protected session (a failing or panicking command leaves the scene and camera as they were), and returns JSON. The UI only calls commands, apart from continuous camera drags, which move `session.camera` directly as SolidCraft's do.

| Id | Does |
|---|---|
| `edit.redo` | make the last undone step again |
| `edit.undo` | put the scene back as it was before the last step |
| `file.open` | replace the scene with the `.rsup` project at `path`: its models unlifted, where they were saved, and their supports; fit the view; start a fresh undo history |
| `file.save` | write the models and supports to `path` (`.rsup`; default the scene's file), keeping the file replaced as `<path>.bak` |
| `file.import_stl` | read an STL from `path`, add it to the scene (at the lift height if `lifted`), frame it unless `fit: false` |
| `model.delete` | remove model `id` and its supports |
| `model.lift` | keep models `ids` (by default the selected ones) at the lift height (`lifted: true`), or let them go where they are |
| `model.list` | the models, their triangle counts, bounds, whether lifted and selected; the lift height |
| `model.move` | move models `ids` (by default the selected ones) `by` [x, y, z] mm |
| `model.place` | set `models: [{ id, position?, rotation?, scale?, lifted? }]`, each measured from the model as imported; without `lifted`, a change of Z alone lets a lifted model go |
| `model.rotate` | turn models `degrees` [x, y, z], about X then Y then Z, around their joint bounds' centre |
| `model.scale` | scale models by `factors` [x, y, z] (or one number), each 0.001 to 1000, along each model's own axes |
| `model.select` | select models `ids`: `replace` (default; empty clears), `add` or `toggle` |
| `scene.clear` | remove every model (and its supports) |
| `scene.lift_height` | put every lifted model's lowest point at `height` mm (0 to 500) |
| `support.add` | a tip on model `model` at `point`, with outward `normal` |
| `support.configure` | merge partial `tip`, `body`, `base`, `raft` into `preset` (default the active one), or pick `active`; validated as a whole; no undo step |
| `support.delete` | remove supports `ids`, by default the selection |
| `support.list` | the supports: tip, normal, model, whether selected, and the route under the preset in use: `path` (contact, tip head, knee if any, foot on the plate), `reachable`, `edited` (placed corners), `fault` (they break a rule), and the `selected_joints` and `selected_segments` the route still has |
| `support.place_joints` | put `joints: [{ support, joint, position }]` (scene, Z ≥ 0); a support still on its worked-out route keeps it as placed corners first |
| `support.reset_preset` | put `preset` (default the active one) back to its built-in values; no undo step, no confirmation |
| `support.reset_route` | give supports `ids` (by default those selected or with a selected part) their worked-out route back |
| `support.select` | select supports `ids` and parts `parts` (`{ support, joint }` or `{ support, segment }`): `replace` (default; clears both, so empty clears), `add` or `toggle` |
| `support.settings` | the support settings: `active` and the `light`, `medium`, `heavy` presets |
| `view.fit` | frame everything for a view `aspect` wide |
| `view.projection` | `perspective`, `orthographic` or `toggle` |
| `view.standard` | `front`, `back`, `left`, `right`, `top`, `bottom`, `iso` |
| `view.turn` | turn the view `degrees` (default 15) `left`, `right`, `up` or `down` |

## Undo and redo
Ported from SolidCraft. A command that changes the scene (its `revision` moves) is one step: `execute` pushes the scene from before, with the command's id and label, keeps the last `MAX_UNDO` (200) and clears redo. `Scene` is cheap to copy (meshes and indexes are shared) and holds everything a step puts back, selection included; the camera is not part of it. `edit.undo` and `edit.redo` swap the scene with a step through `Scene::restore`, which keeps model and support ids and the revision growing: a model id never names another mesh, and nothing keyed on the revision mistakes the restored scene. `Scene`'s models and supports are private so that every change goes through a method that bumps the revision; `every_scene_change_is_undoable` runs each command on a fixture and checks it undoes and redoes exactly.

The support settings (`engine::SupportSettings`: three presets and the active one) live on `Session` beside the camera, not in `Scene`, so a settings change is never a step and undoing a support edit never changes a setting. `SupportSettings::validate` holds the ranges and cross-field rules (contact ≤ upper ≤ body ≤ base diameter, penetration ≤ tip length) that `support.configure` and the stored preferences share; `execute` puts them back when a command fails.

A gesture is one step: `Session::begin_step` merges the commands that follow into the first one's step until `end_step`. A gizmo drag or a dragged or typed panel field opens one; the app closes it once no button is held and no field is typed in. Deleting several models or importing several files is one step. The transform tool takes `history_mark` when it opens; Cancel puts the placements back and `forget_since` drops the tool's steps, unless another command's step came between. Undo and redo put the tool away. Ctrl+Z undoes, Ctrl+Y or Ctrl+Shift+Z redoes; the File menu and the application bar's buttons do the same, their tooltips naming the step.

## Viewport
`viewport::show` allocates the view, runs `navigation::handle`, builds the overlay (`render::Overlay`) and hands a `ViewFrame` to an egui paint callback. `gpu::Renderer` draws into egui's own render pass, which the app opens with a 24-bit depth buffer and 4× MSAA (`DEPTH_BITS`, `MSAA_SAMPLES`): background gradient, models (flat-shaded; inside-out faces tinted red), then support tips (an instanced sphere), then grid and axes, which fade toward the grid's edge. Meshes upload once per model id, as imported, split under 128 MiB per buffer; each model's placement (3×4 rows, the cofactor rows for its normals) and colour are a one-instance vertex attribute.

## Navigation
Ported from SolidCraft. The mouse mapping is a preset table (`prefs::NAV_PRESETS`); the default, Fusion, pans with the middle button, orbits with Shift+middle or the right button, and zooms with the wheel toward the model point under the cursor. Ctrl+left drag orbits in every mapping, Space+left pans, a middle double-click goes home, the arrows turn the view 15° (Shift: 90°), Ctrl+arrows pan. Two-finger trackpad scroll pans, Shift+two fingers orbits, pinch zooms. Other keys: F fits, P toggles perspective, Ctrl+I imports, Ctrl+O opens a project, Ctrl+S saves it (Ctrl+Shift+S: Save As), Ctrl+Z undoes, Ctrl+Y (or Ctrl+Shift+Z) redoes, Tab switches edit mode, T / R / S choose Move / Rotate / Scale, Esc puts the tool away, Delete (or Backspace) removes what is selected in the current mode. Shortcuts stand down only while a text field is being typed in: a button keeps egui's focus after a click, and Tab takes the focus off it.

## Chrome
Ported from SolidCraft, reduced. `toolbar::app_bar` is the always-dark application bar: brand, Home (iso view), File (Open Project…, Save, Save As…, Import STL…, Clear Scene, Undo, Redo, Quit), Undo and Redo buttons, Preferences and the version. `toolbar::ribbon` is under it: the workspace card (Prepare, the only one yet), a tab per edit mode, and the tab's groups of 60 pt buttons (icon over label, group name underneath; View's name opens the standard views). A button whose tool is in use shows pressed; one that can't act is dimmed and its tooltip says why. Icons (`icons.rs`) are SolidCraft's SVG masters in `crates/ui-egui/icons`, parsed once, rasterised with tiny-skia at the size shown and cached as textures; their colours are palette roles resolved for the light or dark theme. Tool dialogs are `ui_kit::Card`s: a 40 pt header (icon, title, close), a padded body of `ui_kit::row`s (70 pt label column, 28 pt controls) and a 48 pt footer with Cancel and OK; Enter is OK, Esc Cancel; the card stays inside the viewport. Colours and sizes come from `theme::Tokens` and `theme::metrics`; `theme::apply` gives egui's own widgets the same style for both themes.

## Text and preferences
Every word on screen is a message in `assets/locales/<language>.json` (English only for now), keyed by a stable id and embedded at build time; `i18n::tr`, `i18n::format` (named placeholders) and `i18n::count` (`.one`/`.other`) look it up in the language the `language` preference names (`system` follows the OS). Tests check that every id-shaped literal in the UI's source, every command label (`cmd.<id>`) and every complete language's message is in place; `cargo xtask lists` keeps the catalogs sorted and `cargo xtask i18n` reports gaps. Settings are rows of the `preference_settings!` table in `prefs.rs` (field, default, page, control), which generates `Prefs`, its defaults, each page's Restore defaults and the Preferences window's rows (`preferences.rs`, a `ui_kit::Card` with a page list). Tool data is a row with no page (`support_settings`), so no Restore defaults wipes it. Preferences are stored as JSON under `prefs::STORAGE_KEY` and read by `prefs::lenient`, ported from SolidCraft: a key that doesn't read falls back to its default alone, and the status bar names it at start. `prefs_writer::PrefsWriter` writes them within a second of a change (native builds; eframe's autosave elsewhere). `ResinApp::run` copies the session's support settings into `Prefs` after any command that changed them.

The support settings card (`support_settings.rs`) is a permanent `ui_kit::Card` (`Buttons::None`: no footer, no close, Esc ignored) shown for as long as Support edition lasts: `ui_kit::segmented` tabs (Tip, Body, Base, Raft), a side view beside its fields (`ui_kit::figure_rows`) whose dimensions light up with their field, Restore defaults behind a modal `ui_kit::Confirm`, and the preset strip. The object settings card (`object_settings.rs`) is its counterpart in Object edition, hidden while the Move, Rotate or Scale card is open: the lift height (a dragged or typed value is one step), whether the selected models are lifted (a mixed box when they differ) and Lift imported models. Every mode change goes through `ResinApp::set_mode`; entering Support edition cancels what is pending (`cancel_pending`: an open transform tool, as its Cancel).

## Edit modes
A left click in the viewport acts on what the edit mode says (`EditMode`, toggled by Tab or the toolbar). In **Object edition** (`objects::handle`) a click on a model runs `model.select` (Shift toggles), elsewhere clears; selected models draw in `model_selected`. In **Support edition** clicks place and select tips (below). Both share `supports::picking_press`, so a navigating press, or one on the gizmo, picks nothing.

## Placement
A model keeps its mesh and BVH as imported and a `Placement`: the imported bounds' centre (`Model::pivot`) moved to `position`, after `scale` along the model's own axes and `rotation` degrees about X, then Y, then Z. `Model::transform` is that as an `Affine3`; nothing is rebuilt when it changes: the GPU draws the imported mesh through it, `Scene::ray_hit` sends the ray into model coordinates through its inverse, and only the scene bounds are recomputed from the vertices. Supports keep their tip and normal in model coordinates too, so they follow any placement exactly. `Scene::revision` changes with any of it and invalidates the pointer's pick cache.

A model can be lifted (`Model::lifted`): `Scene::place` then moves its Z so its lowest point is at `Scene::lift_height` (5 mm until changed, `DEFAULT_LIFT_HEIGHT`), a translation of the bounds just computed. So rotating or scaling it, or moving it across the plate, keeps it there, and `scene.lift_height` moves every lifted model. Moving it up or down lets it go: `model.move` with a Z, or a `model.place` entry whose Z alone changes (the panel copies an unchanged Z exactly); `model.lift` and a `model.place` entry's `lifted` set it outright. The gizmo says it outright on every frame, since a drag rebuilds from the placements it began with (lifted unless a Move drag goes up or down), and the transform tool's Cancel gives back a lift a Z move took. The height lives in `Scene`, not beside the support settings: changing it moves models, so undo must put both back together. The app imports lifted unless the `lift_on_import` preference is off, and keeps the height in the `lift_height` preference (tool data, on no page).

## Move, Rotate, Scale
T, R, S choose a tool (`transform.rs`) on the selection in Object edition: a gizmo and a panel, both live. The gizmo (`gizmo.rs`, ported from SolidCraft) is a constant size on screen, at a lone model's pivot or at the centre of several: arrows, plane squares and a centre ball (free drag in the view plane) for Move; rings for Rotate; square-ended handles along the model's own axes, the ball for all of them, for Scale. Distances snap to round steps at the zoom (`snap_step`), angles to 5°, scale factors to 1 %; Ctrl or Alt drags free. A press on a handle is hit-tested before `navigation::handle`, which then leaves it alone (`ResinApp::gizmo_grab`). A drag reports its change since it began, and each frame runs one `model.place` built from the placements it began with, so nothing piles up. The panel, a `ui_kit::Card`, shows a lone model's placement, measured from the import (position, rotation, scale as % or target mm, *Uniform*), applies each edit at once, and has Reset buttons; OK keeps the changes and puts the tool away, Cancel puts back the placements the selection had when the tool opened. With several models selected, the gizmo acts on all of them: rotating turns them about their joint centre, scaling scales each about its own pivot.

## Support tips
In Support edition. Every model keeps a `MeshIndex` (BVH over its triangles) built at import; `Scene::ray_hit` picks through it, for navigation and supports alike. `supports::handle` runs after `navigation::handle`: with no button down, the pointer's pick (cached until the pointer, camera or scene changes) shows a preview tip on the surface; a plain left press on the surface runs `support.add`, on a tip `support.select` (Shift toggles), elsewhere clears the selection. It acts on the press, picked where it happened: egui turns a click whose pointer moves over 6 px before the release into a drag, which lost tips placed with a moving hand. A press the mouse mapping navigates with (Ctrl+left, Space, a preset's left binding) places nothing; Delete or Backspace runs `support.delete`. Tips are picked within the preset's widest tip radius, and previewed as a sphere that size.

Every tip carries a whole support to the plate (`engine::route`). The tip's axis is the surface normal, turned down until it leans no more than `body.max_angle`. The body goes straight down when that is clear. Otherwise it leans along one direction of that cone and drops straight down from a knee, the shortest such path winning. The body and the base keep `body.clearance` from every model: a segment-to-triangle distance in the scene, through each model's BVH. Supports may cross each other and are never merged. A tip with no path is kept and drawn in `support_unreachable`, and the status bar counts them. Routes are derived, not stored: `support_routes::RouteCache` in the UI redoes them when the scene revision or the preset changes, about 8 ms per frame at most (the oldest first, so a gizmo drag never stalls), and keeps the drawn solids until a route or the selection changes. Placed and selected supports take `support` and `support_selected`.

A support's parts can be selected too (`engine::SupportPart`, in `Scene::selected_parts` beside the selected supports, restored by undo like them): its body segments and its joints, numbered along the route's body. Joint `i` is corner `i` of the body except the foot, so there is always one where the tip meets the body (the head) and one at each knee; segment `i` runs from corner `i` to `i + 1`. Routes are derived, so a number may outlive the route it named (a model moved, a knee gone): drawing and `support.list` skip it, and `support.select` checks only the support. A joint is drawn as the round fill of its bend, the body's width. In Support edition a selected joint (or every joint of a selected support) also gets a handle of the same size in `support_selected`, drawn after everything: solid where it is in front, faded (`HIDDEN_HANDLE_ALPHA`) where the scene hides it, only its near side (`handle_fs`). A press on a handle selects that joint, whatever is in front of it; otherwise the nearest of a joint, the tip or base (the whole support), a body segment (`RouteCache::piece_hit`, ray–sphere and ray–capsule tests) and the model's surface wins. Joints are picked within `JOINT_PICK_SCALE` (1.5) times the body's radius, so a press near a bend takes the joint rather than a column ending in it. Shift toggles. Selected parts take `support_selected`; Delete removes whole supports only.

Selected joints and segments carry the Move arrows (`supports::triad`, the transform tool's gizmo with arrows, planes and ball only), always there in Support edition, at the centre of the joints they move: each selected joint, and both ends of a selected segment where there is a joint (the last segment's foot follows its knee). A drag runs one `support.place_joints` per frame from the positions it began with, one undo step, snapped as Move is (Ctrl or Alt free), Z kept at or above the plate. The first edit stores the support's route as its corners (`Support::corners`, in the scene): from then on its route is those corners, never searched again. Moving its model (a placement whose rotation and scale stay as they were, `scene.lift_height` included) carries the corners with the tip, so the support keeps its shape, even with corners pushed under the plate, which flags it until they are moved back. Turning or scaling the model carries the tip, which stays on the surface, and leaves the corners where they are, so the tip stretches. A placed route is still checked (lean, clearance, a knee above the base) and drawn in `support_unreachable` when it breaks a rule (`Route::fault`); `support.reset_route` gives the worked-out route back. `RouteCache` redoes placed routes first: they cost a few tests and are what a drag moves.

## Project files
A project (`.rsup`) is SolidCraft's design container, reduced (`io::project`, ported from SolidCraft's `crates/io/src/design.rs`): a ZIP holding `container.json` (`resinsupport-container/1`), `document.json` (`resinsupport/1`, Deflated: each model's name and placement, each support's model index, tip and normal in the model's own coordinates and placed corners) and `blobs/<sha256>.mesh` (stored, each distinct mesh once: `RSMESH01`, a `u64` triangle count, nine `f32` per triangle). Nothing derived (transforms, bounds, routes), no ids or selection, and no setting: not the support settings, the lift height or whether a model is lifted, so a project opens unlifted, exactly where it was saved, under the user's own settings. A newer format is refused with a message; entries, sizes, names, CRCs and hashes are checked before anything reaches the scene. `io::write_atomic` (ported from SolidCraft's `safe_write.rs`, reduced) writes beside the target, flushes and renames, after copying the old file to `.bak`.

`file.open` is `Scene::adopt` (models and supports get new ids) and starts a fresh undo history (`noundo`; the step serial keeps counting): undo never brings back the scene a project replaced, so the app asks first when the scene has unsaved changes (`ResinApp::confirm_open`, a `ui_kit::Confirm`). `Session` keeps the scene's file with the revision last saved or opened (`Session::file`, `Session::modified`). The window title shows the file name, starred while modified. A dropped or command-line `.rsup` is opened, then the STLs given with it are imported into it. Saving runs on the window thread for now.
