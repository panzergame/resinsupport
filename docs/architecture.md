# Architecture

| Layer | Crate | Role |
|---|---|---|
| L0 | `geom` | vectors, bounding boxes, triangle meshes and their measures (area, volume), ray hits (watertight test, BVH), segment and triangle distances (BVH box queries), spheres and frustums |
| L1 | `render` | headless view math: the camera, projections, view animations, grid and axis geometry |
| L2 | `slice` | the print job: printer profile, print settings (ranges, cross-field rules, exposure per layer) and the sliced job (layers as runs of grey) |
| L3 | `io` | model file import (STL binary and ASCII), project files (`.rsup`), crash-safe writes |
| L4 | `engine` | the session (scene: models, support tips, selection; camera; undo history) and the command registry |
| L5 | `ui-egui` | the egui front end: viewport renderer (wgpu), navigation, menus, panels |
| apps | `resinsupport` | the desktop app |

Support tips live in `engine::Scene` until supports get settings and generation, then move there.

## Commands
`Session::execute(id, params)` looks the id up in `crates/engine/src/cmd.rs`, runs it on a clone-protected session (a failing or panicking command leaves the scene and camera as they were), and returns JSON. The UI only calls commands, apart from continuous camera drags, which move `session.camera` directly as SolidCraft's do.

| Id | Does |
|---|---|
| `edit.copy` | keep models `ids` (by default the selected ones) and their supports for `edit.paste`, replacing what was copied before; the copies live on `Session`, not in the scene, so copying is no step and a copied model deleted since still pastes |
| `edit.paste` | add copies of what was copied, with their supports and lift, arranged on the plate around the others as `model.arrange` does, and select them |
| `edit.redo` | make the last undone step again |
| `edit.undo` | put the scene back as it was before the last step |
| `file.open` | replace the scene with the `.rsup` project at `path`: its models unlifted, where they were saved, and their supports; fit the view; start a fresh undo history |
| `file.save` | write the models and supports to `path` (`.rsup`; default the scene's file), keeping the file replaced as `<path>.bak` |
| `file.import_stl` | read an STL from `path`, add it to the scene (at the lift height if `lifted`), arrange it on the plate as `model.arrange` does if `arrange`, frame it unless `fit: false` |
| `model.arrange` | arrange models `ids` (by default every model) on the plate around the others, the largest first, each at the free spot nearest the plate's centre (`resin_geom::arrange`): moved across, turned a quarter about Z to lie along the plate or when only that fits (not a model with supports), put down (or at the lift height); those with no room go in a column right of the plate |
| `model.delete` | remove model `id` and its supports |
| `model.lift` | keep models `ids` (by default the selected ones) at the lift height (`lifted: true`), or let them go where they are |
| `model.list` | the models, their triangle counts, bounds, whether lifted and selected; the lift height |
| `model.move` | move models `ids` (by default the selected ones) `by` [x, y, z] mm |
| `model.place` | set `models: [{ id, position?, rotation?, scale?, lifted? }]`, each measured from the model as imported; without `lifted`, a change of Z alone lets a lifted model go |
| `model.rotate` | turn models `degrees` [x, y, z], about X then Y then Z, around their joint bounds' centre |
| `model.scale` | scale models by `factors` [x, y, z] (or one number), each 0.001 to 1000, along each model's own axes |
| `model.select` | select models `ids`: `replace` (default; empty clears), `add` or `toggle` |
| `print.configure` | merge partial `printer`, `layers`, `exposure`, `motion`, `slicing`, `estimates`; validated as a whole; no undo step |
| `print.reset` | put the print settings back to their built-in values (the printer profile stays); no undo step, no confirmation |
| `print.settings` | the printer profile and the print settings: `printer`, `layers`, `exposure`, `motion`, `slicing`, `estimates` |
| `print.slice` | slice the scene with its reachable supports and the print settings, on the calling thread, and keep the job on the session: `layers`, `height`, `volume_ml`, `print_time_s`, `clipped`, `unreachable_supports`, `open_rows`; no undo step |
| `scene.clear` | remove every model (and its supports) |
| `scene.lift_height` | put every lifted model's lowest point at `height` mm (0 to 500) |
| `support.add` | a tip on model `model` at `point`, with outward `normal`; with `parent`, a branch: a straight tip to that support's head, sharing its body |
| `support.configure` | merge partial `tip`, `body`, `base`, `raft` into `preset` (default the active one), or pick `active`; validated as a whole; no undo step |
| `support.delete` | remove supports `ids`, by default the selection; a body goes with its last tip |
| `support.list` | the supports: tip, normal, model, `parent` (a branch's), whether selected, and the route under the preset in use: `path` (contact, tip head, knee if any, foot on the plate), `reachable`, `edited` (placed corners), `fault` (they break a rule), and the `selected_joints` and `selected_segments` the route still has |
| `support.place_joints` | put `joints: [{ support, joint, position }]` (scene, Z ≥ 0); a support still on its worked-out route keeps it as placed corners first |
| `support.reset_preset` | put `preset` (default the active one) back to its built-in values; no undo step, no confirmation |
| `support.reset_route` | give supports `ids` (by default those selected or with a selected part) their worked-out route back |
| `support.select` | select supports `ids` and parts `parts` (`{ support, joint }` or `{ support, segment }`): `replace` (default; clears both, so empty clears), `add` or `toggle` |
| `support.settings` | the support settings: `active` and the `light`, `medium`, `heavy` presets |
| `view.fit` | frame everything for a view `aspect` wide |
| `view.projection` | `perspective`, `orthographic` or `toggle` |
| `view.standard` | `front`, `back`, `left`, `right`, `top`, `bottom`, `iso` |
| `view.turn` | turn the view `degrees` (default 15) `left`, `right`, `up` or `down` |

## Undo and redo
Ported from SolidCraft. A command that changes the scene (its `revision` moves) is one step: `execute` pushes the scene from before, with the command's id and label, keeps the last `MAX_UNDO` (200) and clears redo. `Scene` is cheap to copy (meshes and indexes are shared) and holds everything a step puts back, selection included; the camera is not part of it. `edit.undo` and `edit.redo` swap the scene with a step through `Scene::restore`, which keeps model and support ids and the revision growing: a model id never names another mesh, and nothing keyed on the revision mistakes the restored scene. `Scene`'s models and supports are private so that every change goes through a method that bumps the revision; `every_scene_change_is_undoable` runs each command on a fixture and checks it undoes and redoes exactly.

The support settings (`engine::SupportSettings`: three presets and the active one) live on `Session` beside the camera, not in `Scene`, so a settings change is never a step and undoing a support edit never changes a setting. `SupportSettings::validate` holds the ranges and cross-field rules (contact ≤ upper ≤ body ≤ base diameter, penetration ≤ tip length) that `support.configure` and the stored preferences share; `execute` puts them back when a command fails.

The print configuration (`engine::PrintConfig`: the printer profile and print settings of `resin_slice`) lives there too, for the same reasons. `resin_slice::validate` holds its ranges (`resin_slice::FIELDS`) and cross-field rules (the bottom and transition layers fit in the build height, a pixel is at least 1 µm); `print.configure`, `print.settings` and the stored preferences share one JSON shape, `{ printer, layers, exposure, motion, slicing, estimates }`. `PrintSettings::exposure_for` gives a layer's exposure: bottom, then the transition in even steps that reach neither end, then normal. `PrintSettings::layer_motion` steps light-off, lift height and lift speed through the transition the same way. The print settings card edits it live, shown for as long as Slice edition lasts and only then.

A gesture is one step: `Session::begin_step` merges the commands that follow into the first one's step until `end_step`. A gizmo drag or a dragged or typed panel field opens one; the app closes it once no button is held and no field is typed in. Deleting several models or importing several files is one step. The transform tool takes `history_mark` when it opens; Cancel puts the placements back and `forget_since` drops the tool's steps, unless another command's step came between. Undo and redo put the tool away. Ctrl+Z undoes, Ctrl+Y or Ctrl+Shift+Z redoes; the File menu and the application bar's buttons do the same, their tooltips naming the step.

## Viewport
`viewport::show` allocates the view, runs `navigation::handle`, builds the overlay (`render::Overlay`) and hands a `ViewFrame` to an egui paint callback. `gpu::Renderer` draws into egui's own render pass, which the app opens with a 24-bit depth buffer and 4× MSAA (`DEPTH_BITS`, `MSAA_SAMPLES`): background gradient, models (flat-shaded; inside-out faces tinted red), then support tips (an instanced sphere), then grid and axes, which fade toward the grid's edge. The plate's outline (the printer's display size, centred on the origin) is drawn on the grid in every mode, in `grid_major`. Meshes upload once per model id, as imported, split under 128 MiB per buffer; each model's placement (3×4 rows, the cofactor rows for its normals) and colour are a one-instance vertex attribute.

## Navigation
Ported from SolidCraft. The mouse mapping is a preset table (`prefs::NAV_PRESETS`); the default, Fusion, pans with the middle button, orbits with Shift+middle or the right button, and zooms with the wheel toward the model point under the cursor. Ctrl+left drag orbits in every mapping, Space+left pans, a middle double-click goes home, the arrows turn the view 15° (Shift: 90°), Ctrl+arrows pan. Two-finger trackpad scroll pans, Shift+two fingers orbits, pinch zooms. Other keys: F fits, P toggles perspective, Ctrl+I imports, Ctrl+O opens a project, Ctrl+S saves it (Ctrl+Shift+S: Save As), Ctrl+Z undoes, Ctrl+Y (or Ctrl+Shift+Z) redoes, in Object edition Ctrl+A selects every model and Ctrl+C / Ctrl+V copy and paste the selected ones (`edit.copy`, `edit.paste`; the window system sends these two as Copy and Paste events, and Paste only while its clipboard holds text, so Copy leaves the models' names there), Tab switches edit mode, T / R / S choose Move / Rotate / Scale (then X / Y / Z and an amount type the change in), in Slice edition Page Up / Page Down step the shown layer (Shift: ten) and Home / End jump to the first and last, Esc puts the tool away, Delete (or Backspace) removes what is selected in the current mode. Shortcuts stand down only while a text field is being typed in: a button keeps egui's focus after a click, and Tab takes the focus off it.

## Chrome
Ported from SolidCraft, reduced. `toolbar::app_bar` is the always-dark application bar: brand, Home (iso view), File (Open Project…, Save, Save As…, Import STL…, Clear Scene, Undo, Redo, Quit), Undo and Redo buttons, Preferences and the version. `toolbar::ribbon` is under it: the workspace card (Prepare, the only one yet), a tab per edit mode, and the tab's groups of 60 pt buttons (icon over label, group name underneath; View's name opens the standard views). A button whose tool is in use shows pressed; one that can't act is dimmed and its tooltip says why. Icons (`icons.rs`) are SolidCraft's SVG masters in `crates/ui-egui/icons`, parsed once, rasterised with tiny-skia at the size shown and cached as textures; their colours are palette roles resolved for the light or dark theme. Tool dialogs are `ui_kit::Card`s: a 40 pt header (icon, title, close), a padded body of `ui_kit::row`s (70 pt label column, 28 pt controls) and a 48 pt footer with Cancel and OK; Enter is OK, Esc Cancel; the card stays inside the viewport. Colours and sizes come from `theme::Tokens` and `theme::metrics`; `theme::apply` gives egui's own widgets the same style for both themes.

## Text and preferences
Every word on screen is a message in `assets/locales/<language>.json` (English only for now), keyed by a stable id and embedded at build time; `i18n::tr`, `i18n::format` (named placeholders) and `i18n::count` (`.one`/`.other`) look it up in the language the `language` preference names (`system` follows the OS). Tests check that every id-shaped literal in the UI's source, every command label (`cmd.<id>`) and every complete language's message is in place; `cargo xtask lists` keeps the catalogs sorted and `cargo xtask i18n` reports gaps. Settings are rows of the `preference_settings!` table in `prefs.rs` (field, default, page, control), which generates `Prefs`, its defaults, each page's Restore defaults and the Preferences window's rows (`preferences.rs`, a `ui_kit::Card` with a page list). Tool data is a row with no page (`support_settings`), so no Restore defaults wipes it. Preferences are stored as JSON under `prefs::STORAGE_KEY` and read by `prefs::lenient`, ported from SolidCraft: a key that doesn't read falls back to its default alone, and the status bar names it at start. `prefs_writer::PrefsWriter` writes them within a second of a change (native builds; eframe's autosave elsewhere). `ResinApp::run` copies the session's support settings into `Prefs` after any command that changed them.

The support settings card (`support_settings.rs`) is a permanent `ui_kit::Card` (`Buttons::None`: no footer, no close, Esc ignored) shown for as long as Support edition lasts: `ui_kit::segmented` tabs (Tip, Body, Base, Raft), a side view beside its fields (`ui_kit::figure_rows`) whose dimensions light up with their field, Restore defaults behind a modal `ui_kit::Confirm`, and the preset strip. The object settings card (`object_settings.rs`) is its counterpart in Object edition, hidden while the Move, Rotate or Scale card is open: the lift height (a dragged or typed value is one step), whether the selected models are lifted (a mixed box when they differ) and Lift imported models. Every mode change goes through `ResinApp::set_mode`; entering Support edition cancels what is pending (`cancel_pending`: an open transform tool, as its Cancel).

## Edit modes
A left click in the viewport acts on what the edit mode says (`EditMode`, toggled by Tab or the toolbar). In **Object edition** (`objects::handle`) a click on a model runs `model.select` (Shift toggles), elsewhere clears; selected models draw in `model_selected`. In **Support edition** clicks place and select tips (below). Both share `supports::picking_press`, so a navigating press, or one on the gizmo, picks nothing. In both, a plain press on empty space may start a selection box (`box_select.rs`, ported from SolidCraft): past 6 px of drag it is drawn, and on the release it selects (`model.select` or `support.select`) what it takes, replacing the selection or, with Shift held at the press, adding to it. Dragged rightwards (`box_window`, solid outline) it takes what lies wholly inside, leftwards (`box_crossing`, dashed) what it touches. A model is tested on its bounds' corners first and, when they don't settle it, on its triangles on screen, so a turned model is judged exactly; a support on its tip and its body down to the foot. Esc or a mode change drops the box. In **Slice edition** nothing is picked: the view only navigates, supports draw solid (unreachable ones in `support_unreachable`) without their selection, and the scene is sliced in the background (below). Tab cycles Object → Support → Slice.

## Placement
A model keeps its mesh and BVH as imported and a `Placement`: the imported bounds' centre (`Model::pivot`) moved to `position`, after `scale` along the model's own axes and `rotation` degrees about X, then Y, then Z. `Model::transform` is that as an `Affine3`; nothing is rebuilt when it changes: the GPU draws the imported mesh through it, `Scene::ray_hit` sends the ray into model coordinates through its inverse, and only the scene bounds are recomputed from the vertices. Supports keep their tip and normal in model coordinates too, so they follow any placement exactly. `Scene::revision` changes with any of it and invalidates the pointer's pick cache.

A model can be lifted (`Model::lifted`): `Scene::place` then moves its Z so its lowest point is at `Scene::lift_height` (5 mm until changed, `DEFAULT_LIFT_HEIGHT`), a translation of the bounds just computed. So rotating or scaling it, or moving it across the plate, keeps it there, and `scene.lift_height` moves every lifted model. Moving it up or down lets it go: `model.move` with a Z, or a `model.place` entry whose Z alone changes (the panel copies an unchanged Z exactly); `model.lift` and a `model.place` entry's `lifted` set it outright. The gizmo says it outright on every frame, since a drag rebuilds from the placements it began with (lifted unless a Move drag goes up or down), and the transform tool's Cancel gives back a lift a Z move took. The height lives in `Scene`, not beside the support settings: changing it moves models, so undo must put both back together. The app imports lifted unless the `lift_on_import` preference is off, arranged on the plate unless `arrange_on_import` is off, and keeps the height in the `lift_height` preference (tool data, on no page).

## Move, Rotate, Scale
T, R, S choose a tool (`transform.rs`) on the selection in Object edition: a gizmo and a panel, both live. The gizmo (`gizmo.rs`, ported from SolidCraft) is a constant size on screen, at a lone model's pivot or at the centre of several: arrows, plane squares and a centre ball (free drag in the view plane) for Move; rings for Rotate; square-ended handles along the model's own axes, the ball for all of them, for Scale. Distances snap to round steps at the zoom (`snap_step`), angles to 5°, scale factors to 1 %; Ctrl or Alt drags free. A press on a handle is hit-tested before `navigation::handle`, which then leaves it alone (`ResinApp::gizmo_grab`). A drag reports its change since it began, and each frame runs one `model.place` built from the placements it began with, so nothing piles up. The panel, a `ui_kit::Card`, shows a lone model's placement, measured from the import (position, rotation, scale as % or target mm, *Uniform*), applies each edit at once, and has Reset buttons; OK keeps the changes and puts the tool away, Cancel puts back the placements the selection had when the tool opened. With several models selected, the gizmo acts on all of them: rotating turns them about their joint centre, scaling scales each about its own pivot. With a tool open, the keyboard does what a drag does (`transform::key`, `transform::text`): X, Y or Z picks the axis (Move needs one, Rotate defaults to Z, Scale to every axis; a typed Scale axis is that axis alone, *Uniform* or not), digits, `.` or `,` and `-` (which turns the sign over) the amount, relative: `T X 50` moves 50 mm along X. Each key re-runs `model.place` from the placements the typing began with, and the axis is drawn through the centre. The undo step stays open while typing; Enter keeps the amount as that one step and puts the tool away, Esc (or Ctrl+Z) puts the models back and forgets the step, a gizmo drag or another tool drops what was typed.

## Support tips
In Support edition. Every model keeps a `MeshIndex` (BVH over its triangles) built at import; `Scene::ray_hit` picks through it, for navigation and supports alike. `supports::handle` runs after `navigation::handle`: with no button down, the pointer's pick (cached until the pointer, camera or scene changes) shows a preview tip on the surface; a plain left press on the surface runs `support.add`, on a tip `support.select` (Shift toggles), elsewhere clears the selection. It acts on the press, picked where it happened: egui turns a click whose pointer moves over 6 px before the release into a drag, which lost tips placed with a moving hand. A press the mouse mapping navigates with (Ctrl+left, Space, a preset's left binding) places nothing; Delete or Backspace runs `support.delete`. Tips are picked within the preset's widest tip radius, and previewed as a sphere that size.

Every tip carries a whole support to the plate (`engine::route`). The tip's axis is the surface normal, turned down until it leans no more than `tip.max_angle` from vertical (80° by default, apart from the body's `body.max_angle`). The body goes straight down when that is clear. Otherwise it leans along one direction of that cone and drops straight down from a knee, the shortest such path winning. The body and the base keep `body.clearance` from every model: a segment-to-triangle distance in the scene, through each model's BVH. Supports may cross each other and are never merged. A tip with no path is kept and drawn in `support_unreachable`, and the status bar counts them. Routes are derived, not stored: `support_routes::RouteCache` in the UI redoes them when the scene revision or the preset changes, about 8 ms per frame at most (the oldest first, so a gizmo drag never stalls), and keeps the drawn solids until a route or the selection changes. Placed and selected supports take `support` and `support_selected`.

A support's parts can be selected too (`engine::SupportPart`, in `Scene::selected_parts` beside the selected supports, restored by undo like them): its body segments and its joints, numbered along the route's body. Joint `i` is corner `i` of the body except the foot, so there is always one where the tip meets the body (the head) and one at each knee; segment `i` runs from corner `i` to `i + 1`. Routes are derived, so a number may outlive the route it named (a model moved, a knee gone): drawing and `support.list` skip it, and `support.select` checks only the support. A joint is drawn as the round fill of its bend, the body's width. A selected support lights its tip alone (`Owner::Tip`): its body and base keep their look, since the body may be shared with other tips. In Support edition a selected joint also gets a handle of the same size in `support_selected`, drawn after everything: solid where it is in front, faded (`HIDDEN_HANDLE_ALPHA`) where the scene hides it, only its near side (`handle_fs`). A press on a handle selects that joint, whatever is in front of it; otherwise the nearest of a joint, the tip or base (the whole support), a body segment (`RouteCache::piece_hit`, ray–sphere and ray–capsule tests) and the model's surface wins. Joints are picked within `JOINT_PICK_SCALE` (1.5) times the body's radius, so a press near a bend takes the joint rather than a column ending in it. Shift toggles. Selected parts take `support_selected`; Delete removes whole supports only.

Selected joints and segments carry the Move arrows (`supports::triad`, the transform tool's gizmo with arrows, planes and ball only), always there in Support edition, at the centre of the joints they move: each selected joint, and both ends of a selected segment where there is a joint (the last segment's foot follows its knee). A drag runs one `support.place_joints` per frame from the positions it began with, one undo step, snapped as Move is (Ctrl or Alt free), Z kept at or above the plate. The first edit stores the support's route as its corners (`Support::corners`, in the scene): from then on its route is those corners, never searched again. Moving its model (a placement whose rotation and scale stay as they were, `scene.lift_height` included) carries the corners with the tip, so the support keeps its shape, even with corners pushed under the plate, which flags it until they are moved back. Turning or scaling the model carries the tip, which stays on the surface, and leaves the corners where they are, so the tip stretches. A placed route is still checked (lean, clearance, a knee above the base) and drawn in `support_unreachable` when it breaks a rule (`Route::fault`); `support.reset_route` gives the worked-out route back. `RouteCache` redoes placed routes first: they cost a few tests and are what a drag moves.

A support can branch from another's head (`Support::parent`). A double press on a tip (two presses within egui's `max_double_click_delay`, both tested against the tip itself, since a selected support's head handle is drawn over it) starts a branch: the hover sphere and a line to the parent's head follow the pointer, the status bar says what to do, and the next press on a surface runs `support.add` with `parent`, one step. Any other press, Esc, undo or redo, or a mode change puts it away, leaving the scene and the undo history alone. A branch is a tip alone: straight from its contact to the parent's head, with no bend, body, joint or base of its own (`Route::foot`; its `body` is the shared head alone), so it shares the parent's body. It is flagged when the tip does not leave the surface or goes through a model. A head is known without a route (`engine::support_head`; a branch's is its root's), so a branch never waits on its parent's route, moving the parent's head joint takes the branch's tip with it, and a branch of a branch shares the same head. A parent is never itself a branch (a branch made from a branch's tip joins the same parent) and always comes before its branches in `Scene::supports`. Every tip of a body can be deleted, the original one too, and the body goes with the last of them: when a support goes (by `support.delete` or with its model) and some of its branches stay, the first of them takes the body as placed corners (`route::placed_corners`: the corners placed, or the route as worked out), so the body stays where it was, and the other branches join it. A project file names a branch's parent by its index, always an earlier one, and a copy keeps a branch only with its parent. A branch whose parent has no way to the plate has none either: drawn in `support_unreachable`, counted as unreachable and left out of the slice.

## Slicing
`resin_slice::slice` turns a `SliceInput` (closed triangle soups in scene millimetres, each a model or a support, the profile, the settings and a `Stamp`) into a `SlicedJob`. It is ported from mslicer (`raster/`): triangles are placed in pixels (the plate's centre is the image's, row 0 its +Y edge, then the profile's mirrors), bucketed along Z (`Segments1D`, 100 buckets per solid), cut at each layer's plane `(i + 0.5) · h`, and filled scanline by scanline with a global edge table and an active edge list under the nonzero rule, so overlapping solids print as their union unmerged. A segment's depth change comes from its triangle's normal in pixel space, the map's handedness folded in, so a mirroring profile fills the right side. A row whose depth does not return to zero is counted (`JobStats::open_rows`), never fatal; a solid crossing the plate's edge, under it or past the build height is clipped and counted (`clipped`). Anti-aliasing rasterizes `n` times finer and averages each `n × n` block to grey. Every layer's runs reach `res_x · res_y`: the printer does not clear its buffer. Volume is the grey-weighted lit area times the layer height; print time sums each layer's exposure, light-off, lift and retract (speeds are mm/min).

`resin_slice` has no threads: `slice_with` takes a `for_each_layer` runner. The engine builds the input (`SliceSource::input`, from a `Session::slice_source` snapshot: the scene, sharing its meshes, the preset and the print configuration): each model through its transform, each reachable support routed and tessellated by `SupportTessellator` from `support_primitives`, the same description the viewport draws (`support_routes::solids`), every frustum closed. `print.slice` runs it inline. The job lives on `Session` (`adopt_job`, refused when its stamp no longer matches the scene revision and the hashes of the print configuration and the support preset in use; `job_is_current`), never in `Scene`, never an undo step.

In the app, `slice_runner::SliceRunner` routes and slices on a worker thread, its layers spread over `std::thread::scope` threads (one after another in the browser), with a `Progress` and a `Cancel`. Entering Slice edition starts a job unless the kept or running one matches; **Slice now** restarts it; a change while in the mode starts one 500 ms after the last; **Cancel** stops it and nothing starts on its own until something changes. A finished job whose stamp is stale is dropped and, in Slice edition, a new one starts. The status bar shows the progress, then the layer count, height, volume and print time, and counted warnings: clipped objects, unreachable supports left out, open rows.

### Layer preview
Once a job is kept, Slice edition shows its layers (`layer_preview.rs`). Which ones is UI state on `ResinApp`, as the camera is: no command, no undo step. The slider is an `egui::Area` at the viewport's right edge, so the camera never takes its presses or wheel: two handles (the top one is the shown layer), its number, Z and exposure kind beside it; drag, click or scroll; Page Up / Page Down (Shift: ten), Home / End. A newly kept job keeps the shown layer if it is still in range, otherwise shows its top one. While a slice runs, or the scene changed since, the last job is shown dimmed. A card at the bottom left gives the layer out of the total, its Z, exposure and kind, lit area and its share of the plate, and the lit regions (`Layer::regions`, counted on the runs with 8-neighbours). The ribbon's Preview group switches between **3D** and **Layer**.

The shown layer is decoded on the window thread when it changes, never per frame, one layer per frame at most (`layer_image::LayerImage`): `Layer::decode_into` gives the `res_x · res_y` grey levels, cut into power-of-two tiles no bigger than `max_texture_dimension_2d` (8192 by default, so 11 520 px screens split), each with box-filtered mipmaps built on the CPU (WebGL2 has no compute shaders; a GPU decode waits for a measurement). The renderer uploads them as `R8Unorm` textures, reused while the tiles keep their sizes. In **3D**, `ViewFrame::clip` (in the frame uniform, no new pipeline) discards the model, support and joint fragments above the shown layer's top and under the lowest shown layer's bottom; a cap quad per tile at the cut, placed by undoing the slicer's placement (`PlateMap::to_plate`, mirrors included), fills the lit pixels in `model` with a `cap_edge` outline a pixel or two wide on screen and leaves the dark ones out. Outside Slice edition nothing is cut. **Layer** swaps the 3D view for the image alone (`layer_view.rs`): grey as is, nearest-sampled up close with a pixel grid fading in, inside the plate's outline at the plate's aspect ratio; `navigation::handle_2d` reads the mouse mapping's pan and zoom (an orbit binding pans), the wheel zooms toward the pointer, F fits, and the status bar gives the pixel under the pointer, its place on the plate in mm and its grey level.

## Project files
A project (`.rsup`) is SolidCraft's design container, reduced (`io::project`, ported from SolidCraft's `crates/io/src/design.rs`): a ZIP holding `container.json` (`resinsupport-container/1`), `document.json` (`resinsupport/1`, Deflated: each model's name and placement, each support's model index, tip and normal in the model's own coordinates and placed corners) and `blobs/<sha256>.mesh` (stored, each distinct mesh once: `RSMESH01`, a `u64` triangle count, nine `f32` per triangle). Nothing derived (transforms, bounds, routes), no ids or selection, and no setting: not the support settings, the lift height or whether a model is lifted, so a project opens unlifted, exactly where it was saved, under the user's own settings. A newer format is refused with a message; entries, sizes, names, CRCs and hashes are checked before anything reaches the scene. `io::write_atomic` (ported from SolidCraft's `safe_write.rs`, reduced) writes beside the target, flushes and renames, after copying the old file to `.bak`.

`file.open` is `Scene::adopt` (models and supports get new ids) and starts a fresh undo history (`noundo`; the step serial keeps counting): undo never brings back the scene a project replaced, so the app asks first when the scene has unsaved changes (`ResinApp::confirm_open`, a `ui_kit::Confirm`). `Session` keeps the scene's file with the revision last saved or opened (`Session::file`, `Session::modified`). The window title shows the file name, starred while modified. A dropped or command-line `.rsup` is opened, then the STLs given with it are imported into it. Saving runs on the window thread for now.
